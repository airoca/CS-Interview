- **메모리의 구조를 영역에 따라서 설명해줄 수 있나요?**
    
    ![image.png](attachment:1cac60cd-c747-4892-9757-e82336953bf8:image.png)
    
    - **코드(Text) 영역**
        
        실행할 프로그램의 코드가 저장되는 영역으로, 텍스트 영역이라고도 부른다. CPU는 해당 코드 영역에 저장된 명령어를 하나씩 가져가서 처리하게 된다.
        
    - **데이터(Static) 영역**
        
        전역 변수와 정적 변수가 저장되는 영역으로, 프로그램이 시작하는 동시에 할당되며, 프로그램이 종료되면 소멸한다. (데이터 영역의 특정 주소에 저장하는 것) → 힙이나 스택에 뒀다가 사라지면 안되니까!
        
    - **힙 영역 (Heap)**
        
        사용자가 직접 관리하는 영역이며 메모리 공간이 동적으로 할당 및 헤제된다. 동적으로 할당되므로 new로 생성한 객체가 많아질 수록 힙 영역의 크기가 늘어나게 된다.
        
    - **스택 영역 (Stack)**
        
        함수의 호출에 따른 지역변수, 매개변수, 리턴 값이 저장되는 영역으로, 컴파일 시 크기가 결정된다. 함수의 호출과 함께 할당되고, 함수의 호출이 종료되면 소멸한다.
        
    - **JVM**
        
        운영체제가 자바 프로그램을 실행한다는 것은, 정말 작성된 자바 프로그램을 실행한다는 것이 아니라, JVM을 코드, 데이터, 힙, 스택 영역으로 나누어 실행한다는 것이고, 실제 코드 실행은 할당된 자원을 통해 JVM이 동적으로 관리한다.
        

- **메모리의 힙 영역과 스택 영역의 차이에 대해 설명해주세요.**
    - **스택(Stack) 영역**
        - 지역 변수, 매개 변수를 저장한다.
        - 컴파일 타임에 크기가 결정된다.
        - 스택 크기는 제한되어 있다.
        - 메모리는 높은 주소에서 낮은 주소 방향으로 할당된다.
        - 함수가 종료되면 자동으로 소멸되므로 별도의 관리가 필요 없다.
        - 힙에 비해 속도가 빠르다. (push pop)
    - **힙(Heap) 영역**
        - `new` 연산자를 통해 동적으로 생성된 변수를 저장한다.
        - 런타임에 크기가 결정된다.
        - 메모리 크기에 제한이 없고, 필요에 따라 동적으로 늘어난다.
        - 메모리는 낮은 주소에서 높은 주소 방향으로 할당된다.
        - 사용자가 직접 메모리를 관리하거나, 가비지 컬렉터의 관리가 필요하다.
        - 스택에 비해 속도는 느리다. (접근 주소 계산해야 하므로)

- **메모리의 힙 영역을 너무 크게 잡으면 어떤 일이 생길까요?**
    
    위에서 언급했듯이, 힙 영역은 스택 영역과 다르게 직접 생성된 변수를 제거를 통해 메모리 관리가 필요하다.
    
    만약 메모리의 힙 영역이 너무 크다면, 넓은 힙 영역에 존재하는 동적 변수에 대해 참조 여부를 확인해야 하기 때문에 Garbage Collect의 수행시간이 너무 길어지게 된다.
    
    따라서 Java의 JVM에서도 처음부터 힙 영역을 크게 잡지 않고, Heap 영역이 꽉 찼을 때 GC 진행 후 Heap 영역을 확장한다.
    

- **메모리의 종류에 대해 설명하고, 종류가 여러가지인 이유에 대해 설명해주세요.**
    
    CPU에 가까운 순서대로 레지스터, 캐시, 주기억장치, 보조기억장치가 있다.
    
    물리적 메모리의 종류가 많은 이유는, 접근 속도에 따른 차이를 두기 위해서이다. (레지스터 > 캐시 > 주기억장치 > 보조기억장치)
    
    - 레지스터: 수십 ~ 수백 바이트
    - L1: 32KB ~ 128KB
    - L2: 256KB ~ 1MB

- **OS가 메모리 관리를 해야하는 이유에 대해 설명해주시고, 메모리 관리를 위해 어떤 전략을 사용하는지 설명해주세요.**
    
    우선, 각각의 프로세스는 독립된 메모리 공간을 갖는다. 따라서 각 프로세스는 다른 프로세스의 메모리 공간에 접근할 수 없다. 오로지 '운영체제'만이 운영체제 메모리 영역과 사용자 메모리 영역의 접근에 영향을 받지 않는다. 따라서 OS만이 메모리를 관리할 수 있기 때문에 적절한 관리가 필요하다.
    
    가상메모리를 이용한 Swapping, 페이징 및 세그멘테이션 전략, 고정 길이 할당 / 가변 길이 할당, 압축 등의 방식으로 OS가 메모리 관리를 수행할 수 있다.
    

- **메모리의 fit의 종류 4가지에 대해 설명해주세요.**
    
    First fit : 메모리의 처음부터 검사해서 크기가 충분한 첫번째 메모리에 할당
    Next fit : 마지막으로 참조한 메모리 공간에서부터 탐색을 시작해 공간을 찾음 (하지만 계속 앞으로만 가는 특성 때문에 적합한 공간을 지나칠 수 있다. 한 바퀴 돌면 되돌아오는 방식)
    Best fit : 모든 메모리 공간을 검사해서 내부 단편화를 최소화하는 공간에 할당
    Worst fit : 남은 공간 중에 가장 큰 공간에 할당
