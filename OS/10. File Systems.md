- **RAID란 무엇인가요? RAID의 종류에 대해 설명해주세요.**
    
    RAID는 Redundant Array of Independent Disks의 약자이다. 전체 성능을 향상시키기 위해 동일한 데이터를 중복 저장하는 데 사용된다.
    
    - RAID 0-내결함성이없는 스트립 디스크 어레이
    - RAID 1-미러링 및 이중화
    - RAID 2-메모리 스타일 오류 수정 코드
    - RAID 3-비트 인터리브 패리
    - RAID 4-블록 인터리브 패리티
    - RAID 5-블록 인터리브 분산 패리티
    - RAID 6-P + Q 이중화

- **캐시의 정의와 계층 구조는?**
    
    Cache는 CPU와 메인 메모리 사이의 속도 차이를 줄이기 위해 사용되는 고속 메모리이다. 일반적으로 L1, L2, L3 캐시로 구성되며, L1이 가장 빠르고 작으며, L3는 가장 크고 느리다.
    
    - Cache miss 줄이기 위해서는?
    하드웨어적으로 효율적인 캐시 설계, 적절한 교체 알고리즘 적용, Locality 활용 등이 필요하다.

- **캐시의 지역성 원리를 설명해주세요.**
    
    캐시 메모리는 속도가 빠른 장치와 느린 장치 간의 속도 차에 따른 병목 현상을 줄이기 위한 범용 메모리이다. 이러한 역할을 수행하기 위해서는 CPU 가 어떤 데이터를 원할 것인가를 어느 정도 예측할 수 있어야 한다. 캐시의 성능은 작은 용량의 캐시 메모리에 CPU 가 이후에 참조할, 쓸모 있는 정보가 어느 정도 들어있느냐에 따라 좌우되기 때문이다.
    
    이때 적중율(hit rate)을 극대화하기 위해 데이터 지역성(locality)의 원리를 사용한다. 지역성의 전제 조건으로 프로그램은 모든 코드나 데이터를 균등하게 access 하지 않는다는 특성을 기본으로 한다. 즉, locality란 기억 장치 내의 정보를 균일하게 access 하는 것이 아닌 어느 한순간에 특정 부분을 집중적으로 참조하는 특성이다.
    
    데이터 지역성은 대표적으로 시간 지역성(temporal locality)과 공간 지역성(spatial locality)으로 나뉜다.
    
    시간 지역성 : 최근에 참조된 주소의 내용은 곧 다음에 다시 참조되는 특성
    공간 지역성 : 대부분의 실제 프로그램이 참조된 주소와 인접한 주소의 내용이 다시 참조되는 특성
    

- **캐시 라인에 대해 설명해주세요.**
    - 캐시가 데이터를 저장할 때는 라인(Line)단위로 저장한다.
    - 보통 하나의 캐시 라인은 64바이트 정도
    - 하나의 라인은 다음과 같이 구성된다.
        - | 태그(Tag) | 실제 데이터(Data Block) |
        - **Tag**: "이 데이터는 원래 메모리의 어디 주소에 있었는가?"를 알려주는 정보
        - **Data**: 실제 캐시에 저장된 메모리 내용
    - 캐시가 작기 때문에, 모든 주소를 아무 데나 넣으면 안 됨.
    - 그래서 데이터를 어느 캐시 라인에 넣고 꺼낼지 결정하는 방식이 필요하다
    - 이게 바로 캐시 매핑(Cache Mapping) 방식!

- **캐시 매핑 방식 3가지를 설명해주세요.**
    - **Direct Mapping (직접 매핑 방식)**
        - 캐시를 N개의 라인으로 나누고, 메모리 블록 번호를 기준으로 해당 라인 결정
        - 캐시 인덱스 = (메모리 블록 번호) % (캐시 라인 수)
        - 인덱스 계산이 빠르되, 충돌이 많이 일어난다.
    - **Fully Associative Mapping (완전 연결 매핑)**
        - 인덱스를 사용하지 않음 → 오직 태그 값 전체를 비교
        - 충돌이 없지만, 모든 태그를 비교하느라 탐색 비용이 많이 든다.
    - **Set Associative Mapping (집합 연결 매핑)**
        - Direct와 Fully의 절충안
        - 캐시를 S개의 Set으로 나누고, 각 Set마다 n개의 Line을 가짐 (해당하는 Set을 찾은 후, 전체 태그 비교)
        - Set index = (블록 번호) % (Set 수)
        - 예시 (2-way, 캐시 8라인 → 4셋 * 2라인)
        
        ```java
        Set 0:
          Line 0: Tag + Data
          Line 1: Tag + Data
          ...
        Set 1:
          ...
        ```
