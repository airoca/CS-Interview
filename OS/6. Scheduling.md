- **CPU Scheduling이 무엇인지 설명해주세요.**
    
    CPU 스케줄링은 운영체제가 여러 프로세스 중 어떤 프로세스에 CPU를 할당할지 결정하는 알고리즘입니다. 프로세스가 준비 상태(Ready Queue)에 있을 때 CPU 할당 순서를 결정하며, 선점형(preemptive)과 비선점형(non-preemptive) 방식으로 나뉩니다.
    
    선점형은 실행 중인 프로세스를 중단하고 더 높은 우선순위의 프로세스에 CPU를 넘길 수 있고, 비선점형은 실행 중인 프로세스가 자발적으로 CPU를 반환할 때까지 유지됩니다.
    

- **CPU의 성능 척도엔 무엇이 있는지 설명해주세요.**
    - **CPU Utilization (이용률)**
        - CPU가 놀지 않고 일한 시간
        - CPU가 100% 사용됐다고 해도, 무거운 작업 하나 처리하는 데 오래 걸렸다면 Throughput은 낮고, 가벼운 작업 여러 개를 빠르게 끝냈다면 높다.
    - **Throughput (처리량)**
        - 단위 시간당 처리량, CPU가 얼마나 많은 일을 했는지
    - **Turnaround Time (소요시간, 반환시간)**
        - 프로세스가 도착한 순간부터 완료될 때까지 총 시간
        - 대기 시간 + 실행 시간 + I/O 시간 등 전부 포함
    - **Waiting Time (대기시간)**
        - 프로세스가 Ready Queue에서 기다린 전체 시간의 합
        - CPU에 의해 실행되지 않고 대기한 시간의 총합
    - **Response Time (응답시간)**
        - 프로세스가 Ready Queue에 들어가서 최초로 CPU 얻기까지 걸린 시간

- **선점(preemption)과 비선점(non-preemption)이 무엇인지 설명해주세요.**
    
    선점 방식은, 특정 프로세스가 실행 중이더라도 CPU 할당을 뺏어 다른 프로세스에 부여할 수 있는 방식입니다. System Call, Time Quantum, Interrupt 등에 의해 선점이 일어납니다.
    
    반면, 비선점형 스케줄링은 한 프로세스가 CPU를 자발적으로 반환할 때까지 다른 프로세스가 CPU를 사용할 수 없는 방식으로, 실행 중인 프로세스가 종료되거나 입출력 등의 이유로 스스로 CPU를 반환할 때까지 기다려야 합니다. 
    

- **CPU 스케줄링의 종류에 대해 설명해주세요.**
    - **비선점 (Non-Preemptive)**
        - **First Come First Served(FCFS)**
            - 큐에 도착한 순서대로 실행
            - 최악의 경우 오래 걸리는 문제가 가장 먼저 들어옴
        - **Shortest Job First (SJF)**
            - CPU 점유 시간이 가장 짧은 프로세스에 CPU를 먼저 할당하는 방식
            - 기아 문제 발생
        - **Highest Response Ratio Next**
            - 준비 큐에서 기다리는 프로세스 중 응답 비율이 가장 큰것을 먼저 처리하는 방식
            - 서비스 받을 시간이 분모, 대기 시간이 분자에 있어 대기 시간이 큰 경우 우선순위가 높아진다. (오래 기다렸을수록 → 기아 방지)
    - **선점 (Preemptive)**
        - **Round Robin (RR)**
            - 각 프로세스는 동일한 크기의 할당 시간(time quantum)을 갖게 된다.
            - 할당 시간이 지나면 프로세스는 선점당하고 ready queue 의 제일 뒤에 가서 다시 줄을 선다.
            - Response time 면에서 유리하다.
            - RR의 quantum이 너무 길면 FCFS와 같은 문제가 생기고, 너무 짧으면 Context Switching 비용 문제가 생긴다.
        - **Shortest Remaining Time First (SRTF)**
            - CPU 점유 시간이 가장 짧은 프로세스에 CPU를 먼저 할당하는 빙식
            - SJF 방식에서 선점 방식만 다르다고 보면 된다. 기아 문제 발생
        - **Multilevel Feedback Queue (다중 레벨 피드백 큐)**
            - 각 단계마다 하나의 큐를 두고, 큐 시간 할당량 내에 처리하지 못하면 다음 큐로 보내는 방식
            - 단계가 커질수록 시간 할당량이 커지는 형태

- **Multilevel Queue와 Multilevel Feedback Queue의 차이는?**
    
    핵심 차이는 "큐 간 이동이 가능한가?”에 있다.
    
    - **Multilevel Queue**
        - 프로세스를 특정 큐에 고정시켜서 큐별로 다른 정책으로 스케줄링
        - 고정 우선순위 기반이라 기아(starvation) 문제가 생길 수 있음
    - **Multilevel Feedback Queue**
        - 프로세스의 행동에 따라 큐를 이동하며 스케줄링
        - 처음에는 높은 우선순위 큐(Q0)에 들어감
        - 시간이 지나거나 CPU를 오래 쓰면 점점 낮은 우선순위 큐로 강등
        - I/O 중심의 짧은 작업은 상위 큐에서 오래 머무름
