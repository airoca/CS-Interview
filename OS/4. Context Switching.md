- **컨텍스트란 무엇인가요?**
    
    컨텍스트란 운영체제에서 프로세스가 실행되는 동안, 해당 프로세스에 대한 모든 상태 정보를 말합니다.
    
    - 레지스터 값들 (Program Counter, Stack Pointer 등)
    - 메모리 매핑 정보
    - CPU 상태

- **컨텍스트 스위칭이란 무엇인가요?**
    - **컨텍스트 스위칭**
        
        컨텍스트 스위칭이란, 현재 실행 중인 프로세스나 스레드의 상태(문맥)를 저장하고, 다른 프로세스나 스레드의 상태로 전환하는 과정을 말합니다.
        
        - 현재 실행 중인 작업의 컨텍스트를 TCB/PCB에 저장
        - CPU 스케줄러가 다른 프로세스를 선택
        - 새로 선택된 작업의 컨텍스트를 레지스터에 복원
        - 새 작업 실행 시작

- **컨텍스트 스위칭은 왜 필요한가요?**
    - 하나의 CPU로 여러 개의 프로세스나 스레드를 동시에 실행하는 것처럼 보이게 하여, 자원을 효율적으로 공유하기 위함입니다.
    - I/O 대기 시간을 낭비하지 않고, CPU를 다른 작업에 활용할 수 있어 전체 시스템 자원을 더 효율적으로 사용할 수 있습니다.
    - 모든 프로세스가 CPU를 조금씩 번갈아 사용할 수 있게하여 기아를 방지합니다.

- **프로세스와 스레드의 컨텍스트 스위칭을 비교해주세요.**
    - **프로세스 컨텍스트 스위칭**
        - 현재 실행 중인 프로세스를 다른 프로세스로 전환하는 것
        - 주소 공간, 페이지 테이블, 파일 디스크립터 테이블 등 전체 환경을 전환
        - MMU가 참조할 페이지 테이블을 바꾸고, 이 과정에서 반드시 필요한 것이 TLB 무효화(Invalidate)이며, 이것이 성능 저하의 주요 원인 중 하나이다.
    - **스레드 컨텍스트 스위칭 (같은 프로세스 내)**
        - 같은 프로세스 내의 다른 스레드로 전환
        - 주소 공간은 그대로, 레지스터, 프로그램 카운터, 스택 포인터만 바뀜
        - 커널 스택 차원에서의 변경만 일어난다고 보면 된다!

- **TCB/PCB는 어떻게 저장되나요?**
    - 기본적으로 스레드마다 `task_struct` 구조체가 할당됩니다.
        - task_struct는 각 태스크(스레드 또는 프로세스)별로 커널 힙에 할당되는 구조체
        - 커널 스택은 각 태스크별로 독립적으로 존재하는 고정 크기의 커널 스택 공간
        - 이 구조체는 TCB와 PCB 정보를 모두 담고 있고, 스레드끼리 공유되는 자원 정보(PCB)의 경우 포인터 형태로 저장
        - **TCB**
            - 스레드의 정적인 메타데이터를 저장
            - 스레드 ID, 우선순위, 상태 (Runnable, Waiting 등), 사용자 스택 주소, 커널 스택 주소, 스케줄링 정보 등
        - **커널 스택**
            - 컨텍스트 스위칭 시점의 스냅샷(실행 상태) 저장
            - 레지스터 값 (PC, SP, 레지스터들), 시스템 콜 중이던 경우의 상태 등
    - 구체적인 작업 흐름은 아래와 같습니다.
        - Context 저장
            - CPU가 커널 모드로 전환되며 자동으로 몇 개의 레지스터를 커널 스택에 push
            - 나머지 레지스터들, 스택 포인터 등을 커널 스택에 전부 저장 (push)
            - 이후, 현재 스레드의 커널 스택에 저장된 정보들을 task_struct에 백업 (여기에 커널 스택의 포인터도 있음)
        - Context 복구
            - task_struct에서 context 정보 추출 (레지스터 값들)
            - 레지스터 값을 기반으로 커널 스택의 위치를 포인팅한다.
            - 커널 스택을 통해 나머지 정보 복구
        - 모든 레지스터 값은 100% 커널 스택에 저장된다.
        - task_struct에는 스택 포인터 같은 핵심 문맥만 일부 저장된다.
        → 즉, 완전한 레지스터 복원은 커널 스택을 통해서만 가능하다.
