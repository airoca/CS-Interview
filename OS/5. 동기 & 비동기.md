- **동기/비동기와 Blocking/Non-Blocking을 설명해주세요.**
    - **Synchronous**
        - 작업이 완료될 때까지 다음 코드로 넘어가지 않음
        - 하지만 꼭 멈춰 있는 건 아님, 직접 계속 확인하거나 polling 가능
    - **Blocking**
        - 결과가 나올 때까지 실행을 멈추고 대기함
        - CPU가 할 일이 없음, 대기 상태
        

- **동기/비동기와 Blocking/Non-Blocking 예시를 주세요.**
    - **Blocking + Synchronous**
        - 함수가 끝날 때까지 기다리고, 다음 코드로 넘어감
        
        ```java
        String result = blockingDownload(); // 여기서 끝날 때까지 멈춤
        System.out.println(result);         // 이후 실행
        ```
        
    - **Non-blocking + Synchronous**
        - 다운로드는 호출하자마자 반환되지만, 작업의 순서를 보장하느라 `while` 로 이전 작업의 완료를 기다림
        
        ```java
        startDownload(); // 바로 반환됨
        
        while (!isDone()) {
            System.out.println("됐나?");
        } // 바쁘게 계속 확인하면서 CPU는 일함
        
        System.out.println(getResult());
        ```
        
    - **Blocking + Asynchronous**
        - 작업은 비동기적으로 수행하지만, 이후 코드의 실행이 블로킹됨
        - 비동기로 실행했지만 `get()`에서 CPU가 멈춤
        - 결과가 올 때까지 아무것도 못하고 기다림
        
        ```java
        CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
            // 비동기 작업
            try { Thread.sleep(1000); } catch (Exception e) {}
            return "완료";
        });
        
        String result = future.get(); // ❗ 결과를 받을 때까지 블로킹
        System.out.println(result);
        ```
        
    - **Non-blocking + Asynchronous**
        - 비동기 작업은 백그라운드에서 동작
        - 하지만 내가 직접 확인하면서 제어 흐름은 내 손에 있음
        - CPU는 놀지 않고 busy waiting 중
        
        ```java
        FakeDownloader downloader = new FakeDownloader();
        downloader.start(); // 비동기로 다운로드 시작 (바로 반환)
        
        while (!downloader.isDone()) { // ❗ 계속 상태 확인 (polling)
            System.out.println("계속 확인 중...");
        }
        
        System.out.println("결과: " + downloader.getResult());
        ```
        

- **동기/비동기와 Blocking/Non-Blocking이 혼합된 실생활 예시는 무엇인가요?**
    
    “게임 로딩” 상황을 예시로 들 수 있다.
    
    - 데이터 요청은 논블로킹 I/O로 보냈기 때문에 UI 스레드가 멈추진 않는다.
    - 하지만 게임 로직 자체는 "데이터 받아올 때까지 기다림" 상태라 이후 작업으로 진행되지는 않는다.

- **동시성과 병렬성이 어떻게 다른지 설명해주세요.**
    
    동시성은 멀티 프로그래밍 (Multi-Programming)에서 나온 개념으로, 주기억장치에 여러 프로세스를 적재해서 Context Switching을 통해 **동시에 실행되는 것 처럼 보이게 하는 것**을 의미합니다. 실제로는 동시에 실행되는 것이 아니라, 번갈아 실행하는 것입니다. 싱글 코어에서 멀티스레드를 동작시키기 위한 방식입니다.
    
    병렬성은 멀티 프로세싱 (Multi-Processing)에서 나온 개념으로, **실제로 동시에 여러 프로세스를 병렬적으로 실행**하는 방식입니다. 병렬적으로 실행하기 위해서는 CPU가 멀티코어여야 합니다.
